# DSH Desktop v0.5.5 — Tauri 2

> 本版本聚焦**历史加载体验** + **文件以附件形式进对话** + **一键加载全部历史** + **会话管理三修**，累计修复 20+ 项用户反馈。

## ⚠️ 重点 1：文件以「附件」形式进对话（不再塞进输入框）

拖入 / 📎 选中非图片文件（文本 / 代码 / 二进制）时，不再把文件内容直接写进输入框，而是显示为**附件 chip**（文件名 + 大小 + × 移除）。发送时才物化：

- **小文本**（≤256KB 且非二进制）→ 内容随消息发送；
- **大文件 / 二进制 / 拖拽路径载荷** → 给完整路径让 agent 用文件工具读；
- 图片仍走内核原生附件栏，不受影响。

## ⚠️ 重点 2：一键加载全部历史

新增「加载全部历史」按钮，分批自动加载完整个会话（每批 400 条、批间让帧、10000 条保护上限、可取消），不用再一条条点「加载更早」。加载中显示「已加载 N 条」进度。

## ⚠️ 重点 3：会话管理三修

- **手动排序失效**：React 18 批处理下拖拽状态未及时同步，`onDragStart` 注入 `flushSync` 同步提交，拖拽排序恢复可用；
- **思考中页面被历史折叠拉回底端**：会话事件流在流式期间暂停裁剪（running 门控），不再滚动到底端打断阅读；
- **打开小窗白屏 + 卡死**：浮窗 / 宠物窗的 `build()+show()` 移入独立线程，根治 WebviewWindowBuilder 死锁。

## ⚠️ 已知限制（内核上游，本期不改）

**自定义多模态模型读不到图片**：内核 `dsh-llm-pi-ai` 对未显式声明 `input` 的自定义模型回落 `DEFAULT_INPUT=["text"]`，视觉模型被误判为纯文本、图片被 `MODEL_DOES_NOT_SUPPORT_IMAGES` 拒绝。用户侧绕法：`settings.yaml` 的 `llm-pi-ai` 给该模型手动加 `input: [text, image]`。（已向上游反馈）

## 📦 安装包与版本命名规范

统一命名规范：**tag = `v<X.Y.Z>`（带 v），资产文件名 = `<X.Y.Z>`（不带 v）**，格式 `DSH-Desktop-<类型>-<版本>-<平台>-<架构>`；deb 走标准 `dsh-desktop_<版本>_<架构>.deb`；每个主资产附带同名 `<资产名>.sha256` 边车（内容为 64 位小写 hex + 文件名）。

| 平台 | 资产 |
|------|------|
| Windows x64 | `DSH-Desktop-Setup-0.5.5-win-x64.exe`（安装版）/ `DSH-Desktop-Portable-0.5.5-win-x64.zip`（便携版）|
| Windows ARM64 | `DSH-Desktop-Setup-0.5.5-win-arm64.exe`（实验性）|
| Linux x64 | `DSH-Desktop-0.5.5-linux-x64.AppImage` + `dsh-desktop_0.5.5_amd64.deb` |
| macOS ARM64 | `DSH-Desktop-0.5.5-macos-arm64.dmg` |
| 边车（每资产） | `<资产名>.sha256`（如 `DSH-Desktop-Setup-0.5.5-win-x64.exe.sha256`）|

## 🔄 升级说明

1. 完全退出当前 DSH Desktop（托盘右键 → 退出）
2. 下载对应平台安装包并运行
3. 安装器自动检测旧版并装回原目录（**数据不丢失**）
4. 首次启动自动同步全部插件与设置

> macOS 首次打开如提示「已损坏」，右键 app → 打开，或 `xattr -cr "/Applications/DSH Desktop.app"`。
